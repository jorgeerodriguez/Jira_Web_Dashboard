This month's forecast

What's counted. project = DEVOPS, issue types Story / Task / Bug / Hotfix / Sub-task. "Completed" = the ticket entered the Done status (from the changelog; resolutiondate is unreliable here). "Will Not Do" excluded. Re-opens de-duplicated — each ticket counts once, in its first-completion month. Attributed by current assignee.
Forecast method. Central is a recency-weighted average of the last 3 complete months (the latest heaviest) blended toward the current month’s run-rate — this month’s completions so far, extrapolated over the business days elapsed — weighted by how far into the month we are. Early in the month it tracks the recent-months baseline; it converges to the actual as the month fills in, so the estimate updates day to day. The band is ±1 standard deviation of the recent months, recentered on the estimate. Directional only.
Team. The current Platform Engineering roster. Excludes non-team assignees who occasionally get DEVOPS tickets.
By ticket size. Each ticket's current Estimated Size (Small / Medium / Large / XL); a ticket with none counts as unsized. Rates are tickets closed per month over the same three complete months the forecast weights.
Caveat. Ticket count is throughput, not effort or complexity — a bucket-creation task and a multi-week platform build each count as 1. Read across the team accordingly.

Self-Service SLAs & Agent Success

Request volume, delivery turnaround, SLA compliance, and PE review turnaround for agent self-service requests, bucketed by the skill that created them (from the linked MR's label). Agent success is the share of terminal AI requests that reached Done. Human-side tracking is a follow-up. All hours are business hours — Mon–Fri 08:00–17:00 US/Pacific, holidays excluded, one standard clock, since Audacy's users are overwhelmingly North American. The workflows began 2026-03.

What's counted. DEVOPS issues carrying an agent watermark (a pe-* Jira label). The request type comes from the linked GitLab MR's pe:<skill> label (pe:iac-request / pe:k8s-request / pe:tf-module / pe:troubleshoot), matched to the issue by its DEVOPS- key; an issue with no linked MR falls back to its Jira pe-* label. Delivery turnaround = created → first Done (changelog). Review turnaround = MR opened_at → merged_at. v1 tracks AI requests; human-side is a follow-up.
Business hours. Mon–Fri 08:00–17:00 US/Pacific, company holidays excluded, so a request filed 15:00 and closed 08:00 next morning is 2h, not 17h. Targets are business hours too.
Review median vs. MR turnaround. The per-type review median above keeps one MR per Jira issue (the earliest, for deterministic bucketing), so an issue delivered across several MRs contributes once. The MR turnaround table counts every merged MR. Only merged MRs are ingested, so neither is a queue depth — an MR still open is invisible until it lands.
Targets are calibrated to August capability; the window is 3 months. Most buckets therefore read as breaching, and that is the intended signal, not a fault — it is the gap between a good month and the trailing quarter. Delivery p50 by month created ran 406.7h (Apr), 114.0h (May), 18.0h (Jun), 13.9h (Jul), 3.0h (Aug), so a six-month window would calibrate against a team that no longer exists; the reading improves as Jun/Jul age out. MR turnaround below keeps its own six-month window back to the epoch, since that table is about the whole self-service era.
Population. Delivery-type issues only (Story/Task/Bug/Hotfix/Sub-task). A Feature or Epic is a container for requests, not a request, and its lifetime distorts the median. Roughly 18% of a typical request's turnaround falls after its MR merged — shipped work waiting to be closed out — so an auto-transition on merge would improve every figure here for free.
Agent success (v1). Store-derived: terminal AI requests that reached Done vs Won't Do/Cancelled. Invocation-level success from the CloudWatch GenAI dashboard (DEVOPS-9562) is deferred.
